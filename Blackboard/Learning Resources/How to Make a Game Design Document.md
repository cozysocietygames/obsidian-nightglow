## How to Actually Structure a GDD

A GDD is organized into systems and subsystems. A system is a set of rules, variables and behaviors that work together to produce gameplay. For example:

The movement system defines how the player moves (running, jumping, sliding). The combat system governs attacks, damage, cooldowns and enemy responses. The progression system determines how the player levels up or unlocks abilities.

Each system can be split into subsystems when they're complex enough to need separate documentation.

Organizing by systems is essential: it prevents a single chaotic document, lets programmers implement independent pieces, and keeps the GDD modular — if you change the jump, you only update that section.
